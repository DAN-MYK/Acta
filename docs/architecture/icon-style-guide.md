# Acta Icon Style Guide

Останнє оновлення: `2026-04-30`

## Призначення

Цей документ фіксує мінімальні правила для всіх SVG-іконок у Acta, щоб:

- іконки виглядали як одна система, а не як випадковий набір;
- нові SVG можна було додавати без ручного "підганяння" під існуючі;
- розміри, stroke, відступи й контейнери були передбачуваними в усьому UI.

## Базовий формат

Кожна іконка:

- зберігається окремим `.svg` файлом;
- використовує `viewBox="0 0 24 24"`;
- малюється через `stroke`, а не через великі заливки, якщо немає дуже сильної причини інакше;
- використовує `fill="none"` на кореневому `svg`, крім дрібних акцентних точок або маркерів;
- використовує `stroke="currentColor"`, щоб колір контролювався з UI;
- не містить жорстко прошитих кольорів на кшталт `#000`, `#fff`, `red`.

Базовий шаблон:

```svg
<svg viewBox="0 0 24 24" fill="none" xmlns="http://www.w3.org/2000/svg">
  <path d="..." stroke="currentColor" stroke-width="1.8" stroke-linecap="round" stroke-linejoin="round"/>
</svg>
```

## Розмірна сітка

Канонічна сітка для джерел:

- `24x24` у `viewBox`
- основна геометрія тримається всередині зони приблизно `4..20`
- бажано залишати оптичний внутрішній відступ 2-3 px від краю

Робочі розміри в UI:

- `14` - дрібні індикатори в рядках і бейджах
- `15-16` - іконки дій у кнопках і списках
- `18-20` - секційні або навігаційні іконки
- `24` - прев’ю в галереї
- `32` - лише для демо або великих preview

Правило:

- джерело завжди лишається `24x24`, а масштабування відбувається через `AppIcon`.

## Stroke

Канонічний `stroke-width` для набору:

- `1.8` для більшості іконок

Допустимі відхилення:

- `1.5` для дуже дрібної внутрішньої типографіки на кшталт `PDF`, `Excel`
- `2.0` максимум, якщо без цього форма розвалюється на малому розмірі

Не змішувати в межах однієї іконки:

- дуже тонкі (`1.0-1.2`) і дуже товсті (`2.4+`) лінії поруч

Канонічні параметри stroke:

- `stroke-linecap="round"` для більшості ліній
- `stroke-linejoin="round"` для більшості кутів

Виняток:

- прямокутні або табличні форми можуть жити без явного `linecap`, якщо геометрія і так читається акуратно.

## Відступи та оптичний баланс

Іконка має:

- візуально стояти по центру;
- не прилипати до жодного боку `viewBox`;
- мати приблизно однакову "масу" з іншими іконками набору.

Практичні правила:

- не торкайся контурами краю `0` або `24`;
- уникай надто дрібних деталей, які зникнуть на `14-16px`;
- якщо є текстоподібні елементи, тримай їх короткими: 2-3 лінії або 2-4 знаки максимум;
- якщо іконка виглядає завузькою, краще розширити композицію, а не збільшувати stroke.

## Форми та стиль

Стиль Acta зараз:

- `outline`;
- стриманий, бухгалтерський, не декоративний;
- геометрично чистий;
- з легким product-відчуттям, але без "іграшковості".

Це означає:

- прості первинні форми: прямокутник, картка, коло, стрілка, рядок, чек;
- мінімум декоративних вигинів;
- одна домінантна ідея на одну іконку;
- силует має читатись за 1 секунду без контексту.

Не робимо:

- складні багатошарові ілюстративні SVG;
- дрібний "шум" із багатьох коротких path;
- випадкові filled-елементи без системної причини;
- різні стилі для сусідніх доменів.

## Filled елементи

Filled-деталі дозволені лише як малі акценти:

- точки;
- колеса в накладній;
- маленькі маркери;
- крапки в palette-іконці;

Правило:

- filled-деталі не повинні домінувати над outline-каркасом.

## Контейнери в UI

Сам SVG не повинен знати про фон, падінги чи рамку.

Це робить `AppIcon.svelte`:

- `size` керує фактичним відображенням;
- `surface={true}` додає м’який контейнер навколо іконки;
- колір завжди успадковується через `currentColor`.

Отже:

- не вбудовуй у сам SVG фонові плашки;
- не малюй у файлі окремий rounded square для кнопкової подачі;
- контейнер живе на рівні компонента, не джерела.

## Іменування файлів

Ім’я файлу має бути:

- коротким;
- доменним;
- без зайвих синонімів.

Приклади:

- `invoice.svg`
- `waybill.svg`
- `reconcile.svg`
- `priority-high.svg`
- `open-status.svg`

Правило:

- ім’я файлу може бути kebab-case;
- ключ у `appIcons` може бути camelCase, якщо так зручніше в TypeScript.

## Додавання нової іконки

Процедура:

1. Створи новий `.svg` у [frontend/src/lib/icons](/C:/Users/MykhailoDan/apps/Acta/frontend/src/lib/icons).
2. Дотримайся `viewBox 24x24`, `currentColor`, базового `stroke-width`.
3. Додай імпорт у [frontend/src/lib/icons/index.ts](/C:/Users/MykhailoDan/apps/Acta/frontend/src/lib/icons/index.ts).
4. Якщо іконка доменна, додай мапінг у [frontend/src/lib/icon-maps.ts](/C:/Users/MykhailoDan/apps/Acta/frontend/src/lib/icon-maps.ts).
5. Підключи її через `AppIcon`.
6. Перевір у галереї іконок та в реальному UI-контексті.

## Чекліст перед комітом

Перед тим як вважати іконку готовою, перевір:

- вона читається на `16px`;
- вона не виглядає товщою або тоншою за сусідні;
- вона візуально центрована;
- її форма зрозуміла без тексту;
- вона працює і на світлому, і на темному фоні;
- вона не містить жорстко зашитого кольору;
- вона не дублює вже наявну іконку без причини.

## Коли не треба малювати нову іконку

Не додавай нову SVG, якщо:

- існуюча вже передає той самий сенс;
- різниця лише косметична;
- іконка з’явиться один раз у дуже вузькому контексті й не формує новий патерн;
- сенс краще передається текстом, а не піктограмою.
